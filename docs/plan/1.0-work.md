# 1.0 work: tickets and job-card drafts

**Status:** the spec was approved 2026-10-25. Each ticket has its issue (numbers in the table). The S0 card is in the fleet queue, held; the wave 2 cards are attached once S0 is merged.

The work starts fresh (ADR 0002): nothing from the old plain-JavaScript code is carried over. Its branches stay for reading; a card may point a worker at one as an example, never as code to copy.

## How the work is cut

- **Thin slices.** Each ticket ends in something you can see or test, not a layer.
- **Pure logic first, on its own.** The outline model, the OPML codec and the ODT writer are pure functions with no Nextcloud or browser in them. They are the S, exact cards, with expected values written into the card, and they go to Qwen.
- **Every editing change goes through one command list** from the start, so undo (M5) covers it without a retrofit.
- **Lanes:** S exact → `qwen`; M with judgement → `chatgpt`; L or design-heavy → `claudeapi`. A review always runs on a lane other than the author's, with the lane set explicitly.
- **Checks:** JavaScript and PHP checks build nothing heavy and run `light`. The Vue build (`npm run build`) is a build and goes through the gate.

### nco-t1a-opml-codec  OPML read and write (PHP, pure)
```
issue:     iannitram/nc-outliner#85
goal:      M1/M4/M6: one place that turns OPML text into a tree and back, losing nothing the app stores
scope:     in: parse(string): Tree and write(Tree): string; row fields text, note, id, collapsed, children; app namespace xmlns:nco="https://github.com/iannitram/nc-outliner/ns/1"; standard _note attribute for notes so OmniOutliner reads them.
           out: file access, controllers, checkbox state (T11 adds it)
done-test: 8 named PHP tests, all failing on the stub base and passing after; values below
files:     the codec file and its test file S0 sets aside (named in the card once S0 is merged)
plan:      builder qwen (Qwen3-Coder); reviewers correctness chatgpt; repeated runs none
hardware:  any
flags:     none
after:     nco-s0-skeleton
```
Expected values (hard-coded; the worker derives none):
1. `<outline text="A"/>` in a body → one root row, text "A", note "", collapsed false, no children, an id assigned (non-empty).
2. `<outline text="A" _note="n1"/>` → note "n1".
3. `<outline text="A" nco:id="r7" nco:collapsed="true"><outline text="B"/></outline>` → id "r7", collapsed true, one child "B".
4. Text with `&amp; &lt; "` round-trips byte-for-byte through write then parse.
5. Write of a tree with a note emits `_note="..."` and never `nco:note`.
6. Write then parse of a 3-level tree (A > B > C, plus D at root) gives the same tree, ids kept.
7. A row without `nco:id` gets a new id on parse; two such rows get different ids.
8. Invalid XML → a typed parse error, never a partial tree.

### nco-t2a-outline-model  Outline tree and its operations (JS, pure)
```
issue:     iannitram/nc-outliner#86
goal:      M2/M3/M8: the one set of tree operations the editor, undo and drag all use
scope:     in: insertAfter(tree, id, newRow), remove(tree, id), indent(tree, id), outdent(tree, id), moveUp(tree, id), moveDown(tree, id); each returns a new tree and leaves the input unchanged; children always move with their row.
           out: Vue, keyboard handling, undo
done-test: 12 named vitest tests, failing on the stub base and passing after; values below
files:     the model file and its test file S0 sets aside
plan:      builder qwen (Qwen3-Coder); reviewers correctness chatgpt
hardware:  any
flags:     none
after:     nco-s0-skeleton
```
Start tree for every case, written as indented text: `A`, `  A1`, `  A2`, `B`, `C`.
1. insertAfter(A1, X) → A[A1, X, A2], B, C.
2. insertAfter(C, X) → A[A1, A2], B, C, X.
3. remove(A) → B, C (A1 and A2 go with it).
4. remove(A2) → A[A1], B, C.
5. indent(B) → A[A1, A2, B], C.
6. indent(A) → unchanged (no row above at its level).
7. indent(A2) → A[A1[A2]], B, C.
8. outdent(A2) → A[A1], A2, B, C.
9. outdent(B) → unchanged (already at top).
10. moveUp(B) → B, A[A1, A2], C.
11. moveDown(A1) → A[A2, A1], B, C.
12. The input tree is deep-equal to its start state after every call above.

### nco-t13a-odt-writer  Outline to ODT content (PHP, pure)
```
issue:     iannitram/nc-outliner#87
goal:      M7: the heading rule, as a pure function the publisher calls
scope:     in: contentXml(Tree): string producing ODT office:text with text:h and nested text:list; a note becomes a text:p right after its row's heading or inside its list item.
           out: zipping the .odt, the folder picker, saving, opening in Nextcloud Office (T13b)
done-test: 6 named PHP tests on the element sequence, failing on the stub base and passing after; values below
files:     the writer file and its test file S0 sets aside
plan:      builder qwen (Qwen3-Coder); reviewers correctness chatgpt
hardware:  any
flags:     none
after:     nco-s0-skeleton
```
Sample tree: `Plan` (note "Why"), `  Goals`, `    Ship`, `    Test`, `  Risks`, `Done`.
Expected sequence (element, level, text):
1. text:h 1 "Plan"; text:p "Why".
2. text:h 2 "Goals" (second level, has children).
3. text:list > text:list-item "Ship", text:list-item "Test" (bullets under Goals).
4. "Risks" (second level, no children) → text:list-item "Risks" at list level 1, not a heading.
5. text:h 1 "Done".
6. Text with `&` and `<` is escaped; output parses as XML.
